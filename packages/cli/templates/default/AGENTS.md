# Runable project

This project uses Runable, a Vue framework designed to work across different
server runtimes rather than shipping its own. Your backend (Express,
Fastify, NestJS, AdonisJS, Hono, Koa, or a custom server) owns HTTP, APIs,
and business logic; Runable adds routing, layouts, SSR, and auto-imports for
the Vue layer around it.

Docs: https://runable.netlify.app/docs

## Project structure

```
app/
├── pages/         # File-based routes
├── layouts/       # Layouts wrapping pages
├── components/    # Auto-registered Vue components
├── composables/   # Auto-imported composables
├── globals/       # Auto-imported global functions/variables
├── middlewares/   # Route middleware
└── plugins/       # Vue app plugins

runable.config.ts  # Framework configuration (defineConfig)
```

- `app/pages/` — file-based application routes.
- `app/layouts/` — layouts wrapping pages.
- `app/components/` — Vue components, auto-registered globally.
- `app/composables/` — composables, auto-imported.
- `app/globals/` — global functions/variables, auto-imported.
- `app/middlewares/` — route middleware.
- `app/plugins/` — Vue app plugins (`defineVuePlugin`).
- `runable.config.ts` — framework configuration, authored via `defineConfig`
  from `"runable"`.

All of the above are configurable in `runable.config.ts`; these are just the
defaults. Check that file before assuming a directory has been renamed.

## Development commands

- Install dependencies: `pnpm install` (or the package manager this project
  actually uses).
- Generate/refresh Runable's generated types and config: `pnpm app:prepare`
  (runs `runable prepare`).
- Build for production: check `package.json`'s `scripts` for the one that
  runs `runable build` — it's named `app:build` in a regular project, but
  `build` in a Runable module. Use whichever is actually declared; don't
  assume either name.
- There is no `runable dev` command. If this project has its own backend
  entry point (e.g. `server.ts`), start development the same way you'd run
  that server normally — check `package.json`'s `scripts` first rather than
  assuming a command exists.
- In general: before running any command mentioned in this file, confirm it
  is actually declared in `package.json`'s `scripts` — don't invoke a
  command that isn't there.

## Runable conventions

- Routes are generated from `app/pages/`.
- Layouts belong in `app/layouts/`.
- Route middleware belongs in `app/middlewares/`.
- Vue app plugins belong in `app/plugins/`.
- Framework configuration belongs in `runable.config.ts`, via `defineConfig`.

## TypeScript

- Prefer TypeScript for application code.
- Keep public interfaces (composables, plugin options, module options)
  strongly typed.
- Avoid `any` unless strictly necessary.
- `runable prepare` generates `.app/tsconfig.app.json` describing the
  project's types — typecheck against it once it exists:
  `tsc -p .app/tsconfig.app.json`.

## Vue

- Use Vue 3 with the Composition API.
- Prefer `<script setup lang="ts">`.
- Keep components strongly typed.

## Generated files

`.app/` and `.output/` are generated by Runable (`runable prepare` /
`runable build`) — never edit files inside them by hand. If something in
there looks wrong, fix the source (application code or `runable.config.ts`)
and regenerate with `pnpm app:prepare` / the project's build script instead.

## Before finishing a change

When applicable:

1. Run `pnpm app:prepare` if you changed routes, middleware, modules, or
   `runable.config.ts`.
2. Typecheck (`tsc -p .app/tsconfig.app.json` once it exists).
3. Run this project's tests, if it has any.
4. Run the build script declared in `package.json` (`app:build` or `build`
   — see "Development commands") to confirm the change builds.

Don't stop at "done" after editing a file — confirm the change with the
commands above.
